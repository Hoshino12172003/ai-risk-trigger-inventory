# M5 Data Integration Audit

## Status

`BLOCKED_MISSING_LOCAL_INPUT`

The expected local directory is `data/local/m5/`. It is covered by the
repository-wide `data/local/` ignore rule. No M5 file is downloaded or committed.
The four expected files were not present during this audit:

- `sales_train_validation.csv`
- `sales_train_evaluation.csv`
- `calendar.csv`
- `sell_prices.csv`

Consequently, empirical row counts, dimensions, date coverage, missingness,
duplicate keys, zero-sales prevalence, and price missingness are not reported.
They must be generated by rerunning `audit_m5_inputs.py` after local files are
provided; inventing those values would violate the audit boundary.

## Parameter provenance

OBSERVED M5 fields are unit sales, item/department/category identifiers,
store/state identifiers, sell price, calendar events, and SNAP indicators.

DERIVED candidates are lagged demand, rolling mean and volatility, price-change
or promotion proxies, seasonal features, concentration, and demand shifts. All
rolling demand features must lag before rolling.

CALIBRATED optimization fields remain warehouse nodes, inventory, capacity,
transport cost, shortage penalty, and reconfiguration cost. M5 stores are sales
locations and must not be described as observed warehouses.

## Third-paper role

M5 is suitable in principle as a cross-domain validation dataset because its
item-store hierarchy, daily demand history, weekly sell prices, events, and
state-specific SNAP indicators offer context that differs from Favorita.
Suitability remains provisional until the local schema audit passes.

M5 adds explicit sell-price histories and SNAP program indicators. The current
Favorita panel instead provides observed transaction counts and an explicit
`onpromotion` measure; those are not direct M5 fields. Both domains can use the
same uncertainty output contract, `demand_center` and `demand_deviation`, but
M5 needs a separate feature builder because its wide `d_*` sales layout,
calendar join, price join, hierarchy, and availability patterns differ.

No Paper-2 optimizer or AI training was run for this audit.
